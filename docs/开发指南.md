# 开发与本地验收

用 JDK 21、Node.js 24 和仓库中的 Gradle Wrapper。IDEA 的测试插件和配置与日常 IDEA 分开。

```bash
./gradlew spotlessCheck test buildPlugin uiTestJar
node scripts/verify-connected.cjs --ui-only
```

`test` 运行 Kotlin 单元和 Unix Socket 集成测试。`buildPlugin` 输出 `build/distributions/leximeet-idea-0.0.1.zip`，`uiTestJar` 输出独立的 UI 测试驱动。应用格式化使用 `./gradlew spotlessApply`。

## IDEA 的选择顺序

Gradle 依次使用 `-PleximeetIdeHome`、`LEXIMEET_IDE_APP`、`IDEA_HOME` 中第一个显式配置。未配置时会检查系统常用安装位置和 PATH 上的 IDEA 启动器。macOS 检查 `/Applications` 与用户的 `Applications`，Linux 还检查常见 `/opt`、Snap 和 Toolbox 安装目录。

兼容的本地 IDEA 有产品元数据、匹配系统架构的启动器及内置 JBR，构建分支至少为 `252`。显式指定的目录无效会直接报错。未指定且没有兼容的本地 IDEA 时，Gradle 才解析默认的 IDEA `2025.2.6.2` 安装包。`--offline` 会禁止下载，适合验证本地复用。

自动化启动 Gradle 记录在 `build/leximeet/idea-home.txt` 中的同一套 IDEA。`./gradlew prepareTestIde` 可单独查看选择结果。

## 独立 IDEA 与桌面端联调

先准备包含 IDEA 连接功能的 Desktop 工作树，并初始化该提交锁定的 Core 子模块。联调启动实际的 Electron Desktop、Java Core 与词典。

已发布的 Desktop 1.0.1 只有浏览器连接入口。IDEA 需要包含 IDEA 发现、认证与只读授权的 Desktop 构建。同一台电脑可保留 1.0.1，并另外运行独立源码沙箱做联调。

```bash
export LEXIMEET_DESKTOP_ROOT="/absolute/path/to/leximeet-desktop"
(
  cd "$LEXIMEET_DESKTOP_ROOT"
  npm ci --ignore-scripts --no-audit --no-fund
  npm run install:electron
  npm run build
)
./gradlew spotlessCheck test buildPlugin uiTestJar
node scripts/verify-connected.cjs --full-decompiler
```

脚本默认用 Desktop 锁定版本的 Electron，可通过 `LEXIMEET_ELECTRON_EXECUTABLE` 复用已有的同版本可执行文件。每次创建独立目录，使用自生成项目和 JAR。截图、阶段与失败日志写入脚本显示的目录，可用 `LEXIMEET_IDEA_TEST_OUTPUT` 指定父目录。脚本退出时关闭本次进程。

IDEA 测试关闭启动画面，在项目窗口创建前禁止激活 macOS 前台，随后直接向隔离进程的 Swing 组件派发事件。Desktop 使用隐藏、静音的 Electron 窗口。macOS 需要 Xcode Command Line Tools，测试使用与浏览器联调相同的只读前台监测器。检测到任一测试应用抢占前台时本次测试失败，运行目录会保留 `background-focus.json`。Linux 在专用虚拟显示中运行，例如 `xvfb-run -a node scripts/verify-connected.cjs --ui-only`。 [IDEA 命令行选项](https://www.jetbrains.com/help/idea/working-with-the-ide-features-from-command-line.html)

`--ui-only` 覆盖未连接、重新检测、明暗窄窗和原生设置保存。端到端联调还验证打开自动匹配、手动刷新、收起与重新打开、真实收藏标签、组合筛选、表头排序后定位、右侧词卡、重连恢复及双方断开。默认端到端命令在隔离 IDEA 中使用 `.class` 签名视图。加 `--full-decompiler` 会在沙箱为自生成的 JAR 预置反编译确认并验证真实方法体。

## 从 IDEA 启动调试并连接 Desktop

1. 在终端启动兼容的 Desktop。首次构建需要 JDK 21 和 Maven 3.9 或更高版本。安装依赖并完成构建后，后续可直接用同一资料目录运行 `npm run dev`。把示例占位路径换成真实绝对路径。

   ```bash
   cd "/absolute/path/to/leximeet-desktop"
   git submodule update --init --recursive
   npm ci --ignore-scripts --no-audit --no-fund
   npm run install:electron
   npm run build
   LEXIMEET_DATA_DIR="$HOME/.leximeet/idea-debug" npm run dev
   ```

   保持 Desktop 运行。只读服务就绪后，会在这套资料目录下创建 `idea-connector/lmcp-uds.json`。

2. 用 IDEA 打开插件 Gradle 工程，创建 **Gradle** 运行配置。将 **Tasks and arguments** 设为 `runIde -PleximeetDesktopProfile=/absolute/path/to/profile`，其中 `profile` 要与 Desktop 的 `LEXIMEET_DATA_DIR` 完全相同。路径带空格时加双引号。选择 JDK 21 为 Gradle JVM，点击 **Debug**。如果本地已经缓存好全部依赖，可选加 `--offline`。

   从插件仓库的终端运行同一任务也可以。

   ```bash
   ./gradlew "-PleximeetDesktopProfile=$HOME/.leximeet/idea-debug" runIde
   ```

   也可在 Gradle 配置的环境变量中填写 `LEXIMEET_IDE_DESKTOP_PROFILE`。同时设置时，`-PleximeetDesktopProfile` 优先。Gradle 会把目录作为 `-Dleximeet.desktop.profile` 传给沙箱 IDEA 的 JVM。正常安装且具备 IDEA 连接能力的 Desktop 使用日常资料目录时，直接运行 `./gradlew runIde` 即可自动发现。

3. 在沙箱 IDEA 打开一个项目，在底部 **词遇** 选择 **连接桌面端 → 确认只读连接**。窗口会自动加载命中，**刷新** 可手动重查。试着组合搜索、学习状态和标签筛选，再点击列名排序。点选单词或按 **Enter** 检查右侧词卡及定位。持续高亮默认关闭，可从工具窗顶部的开关或 **设置 → 工具 → 词遇** 开启。

如果仍显示 **未发现桌面端**，先确认两端资料目录相同、Desktop 仍在运行，以及上面的发现文件已经生成。若已连接但词表为空，检查 Desktop 当前学习目标和收藏范围，然后打开包含目标词的文本，或展开对应的项目树目录。

## GitHub Actions

`main` 推送、PR 和手动运行会触发「IDEA 开发检查」。它先运行 Spotless、单元和 Socket 测试、原生 IDEA UI，再检出固定的 Desktop 提交及其 Core gitlink，运行真实端到端联调。测试报告、阶段日志和截图会上传，全部通过才上传候选 ZIP。CI 附件只收集测试证据。

GitHub 的 Ubuntu runner 使用 Xvfb 隔离 Swing 和 Electron 界面，优先复用已安装的 IDEA Community 2025.2.6.4。缺少该版本时，CI 从 JetBrains 官网下载一个发行包并验证 SHA-256。构建和界面测试共用这套 IDE，覆盖最低兼容分支 `252`。开发机仍优先复用已安装的兼容 IDEA。

版本标签复用同一个验证流程。开发和 CI 使用选定的一套 IDEA，跳过会下载多套 IDE 的 `verifyPlugin`。发布的签名验证只处理 ZIP。签名、草稿和 Marketplace 配置见[发布指南](发布指南.md)。
