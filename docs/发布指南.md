# 词遇 IDEA 发布指南

插件 ID 是 `com.github.weilhuang.leximeetidea`，Marketplace 名称为 `LexiMeet`。版本以 `gradle.properties` 中的 `version` 为准。正式 ZIP 包含插件描述、图标、许可证与第三方声明。Marketplace 简介和英文更新说明来自 `src/main/resources/META-INF/plugin.xml`，仓库的中文变更记录在 `CHANGELOG.md`。

## 首次发布 0.0.1

1. 确认 `.github/workflows/build.yml` 固定的 Desktop 和 Core 提交在各自的 GitHub 仓库可读取，面向用户提供带 IDEA 连接能力的 Desktop。插件通过本机 Unix Domain Socket 连接桌面端，首版支持 macOS / Linux，安装时需要兼容的 Desktop 与 Core。
2. 按[开发指南](开发指南.md)验收，并检查 `main` 上的 GitHub Actions。确认发布范围后，由维护者在 IDEA 插件仓库创建并推送版本标签：

   ```sh
   python3 scripts/check-release-archive.py --tag v0.0.1 --version-only
   git status --short
   git tag -a v0.0.1 -m '词遇 IDEA 0.0.1'
   git push origin refs/tags/v0.0.1
   ```

3. 标签流水线核对标签、插件版本及提交是否属于 `main`，再执行格式检查、单元测试、Socket 集成测试、原生 UI 和真实桌面端联调。验收后签名，并创建 GitHub Release **草稿**。草稿中的 `leximeet-idea-0.0.1.zip` 已签名，同名 `.sha256` 可用于核对下载文件，也可在该次 Actions 的 `idea-signed-release` 产物中取得这两个文件。
4. 登录 [JetBrains Marketplace 首次上传页面](https://plugins.jetbrains.com/plugin/add)，从有权限的 Vendor 上传草稿里的签名 ZIP。选择与仓库 `LICENSE` 一致的许可证并填写公开源码地址 `https://github.com/leximeet/leximeet-idea`，检查表单显示的版本、兼容范围、插件描述与标签。首发使用 Stable 时让渠道留空；审核通过后还需控制公开时机时，可按 Marketplace 提供的选项先设为隐藏。Vendor 的协议和账号声明由维护者确认。`v0.0.1` 的 Marketplace 上传始终由维护者在网页提交。
5. 检查 GitHub 草稿及 Marketplace 审核状态。公开 GitHub Release 和 Marketplace 可见性由维护者决定，标签流水线不会替维护者公开 GitHub 草稿。

重跑标签时，已有附件须与本次签名产物一致。流水线会补传草稿里缺少的附件；已有附件或公开链接对应的文件不会被覆盖。请留意证书有效期。

[Marketplace 首次上架](https://plugins.jetbrains.com/docs/marketplace/uploading-a-new-plugin.html) · [JetBrains 插件签名](https://plugins.jetbrains.com/docs/intellij/plugin-signing.html)

## 签名材料和本地签名

已有签名材料可复用。需要新生成时，在插件仓库运行以下命令，将材料写到仓库外一个尚不存在的绝对路径。脚本交互式读取口令，生成加密的 4096 位 RSA 私钥和自签证书。私钥和口令分别存入受控位置。证书是公开验证材料，签名 ZIP 会携带它用于验签。

```sh
bash scripts/generate-signing-keys.sh "$HOME/leximeet-idea-signing"
```

需要在本地预演时，先完成本地验收并构建 `buildPlugin`，运行以下命令。脚本需要 JDK 21 或更新版本，并在终端隐藏输入口令。参数只含文件路径；本地签名用不到 `PUBLISH_TOKEN`。

```sh
bash scripts/sign-release.sh \
  "$PWD/build/distributions/leximeet-idea-0.0.1.zip" \
  "$PWD/build/leximeet-idea-0.0.1-signed.zip" \
  "$HOME/leximeet-idea-signing/chain.crt" \
  "$HOME/leximeet-idea-signing/private.pem"
```

本地预演的签名包和 SHA-256 使用独立文件名。正式发布使用标签流水线中同一次通过测试、签名和校验的附件。

## GitHub Actions 配置

在 **Settings → Secrets and variables → Actions → Secrets** 添加或更新仓库 Secrets。已有值无需重复配置。前三项只在签名步骤使用；`PUBLISH_TOKEN` 只在后续自动上传步骤使用。

| Secret | 值 |
| --- | --- |
| `LEXIMEET_SIGNING_CERTIFICATE` | 完整 `chain.crt`，保留首尾行和换行 |
| `LEXIMEET_SIGNING_PRIVATE_KEY` | 完整的加密 `private.pem`，保留首尾行和换行 |
| `LEXIMEET_SIGNING_PASSWORD` | 私钥口令 |
| `PUBLISH_TOKEN` | 由有权发布该插件的账号在 Marketplace **My Tokens** 生成 |

也可以用 GitHub CLI 从仓库外的文件或交互终端写入。以下命令可从 Fish 使用。不要把私钥、口令或 Token 写到命令参数、项目文件、GitHub Variables 或发布附件中。

```sh
# 只有首次配置或需要轮换时才运行。
gh secret set LEXIMEET_SIGNING_CERTIFICATE --repo leximeet/leximeet-idea < "$HOME/leximeet-idea-signing/chain.crt"
gh secret set LEXIMEET_SIGNING_PRIVATE_KEY --repo leximeet/leximeet-idea < "$HOME/leximeet-idea-signing/private.pem"
gh secret set LEXIMEET_SIGNING_PASSWORD --repo leximeet/leximeet-idea
gh secret set PUBLISH_TOKEN --repo leximeet/leximeet-idea
```

桌面端联调、依赖下载和打包不读取这些 Secrets。签名器读入密钥和口令后，在同一 Java 进程签名与验签，随后检查签名 ZIP 去掉签名后是否与已测试的包逐字节一致。归档检查还校验外层 ZIP 与内层 JAR 的允许清单。只上传签名 ZIP 和校验文件；CI 测试报告来自隔离的测试资料。

## 后续版本自动提交 Marketplace

1. 插件完成首次网页提交并建立 Marketplace 条目后，确认 Token 所属账号有该条目的发布权限。
2. 在 **Settings → Environments** 创建 `marketplace`，建议限制为指定版本标签，按团队需要设置审批。已有仓库 `PUBLISH_TOKEN` 可直接使用；前三项签名 Secrets 仍留在仓库 Secrets。
3. 在 **Settings → Secrets and variables → Actions → Variables** 将 `LEXIMEET_MARKETPLACE_TAG` 设置为要验证的确切标签（例如 `v0.0.2`）。只有该标签会提交。需要长期自动上传时，另行设置 `LEXIMEET_PUBLISH_MARKETPLACE=true`。两个变量都未设置时只生成签名草稿。`v0.0.1` 始终跳过 Marketplace 任务。
4. 后续标签通过全部检查并生成草稿后，流水线将同一份签名 ZIP 提交到 Stable，并核对回执的版本和更新 ID。回执表示上传成功；在 Marketplace 审核通过前，公开页面可能仍查不到。第一次提交仍在审核时，若服务拒绝新增版本，先核对真实 Vendor 的权限、首版审核状态和该版本是否已收到，再重跑上传任务。

[Marketplace Token](https://plugins.jetbrains.com/docs/intellij/publishing-plugin.html#providing-your-personal-access-token-to-gradle) · [Marketplace 更新 API](https://plugins.jetbrains.com/docs/marketplace/plugin-upload.html)

## 从同一提交的成功验收恢复发布

标签流水线因托管环境故障重复失败时，可使用同一提交已经完整通过的「IDEA 开发检查」候选包。先确认待恢复版本尚未提交 Marketplace，再在默认分支触发下列命令，将两个参数换为实际标签和成功 run ID。

```sh
gh workflow run release.yml --repo leximeet/leximeet-idea --ref main \
  -f release_tag=v0.0.2 -f tested_run_id=123456789
```

恢复流程核对注解标签、版本、源码提交、运行仓库、工作流和成功状态，下载该次成功运行的候选 ZIP。签名、草稿与 Marketplace 上传仍使用原标签。若给 `marketplace` 环境设置了部署限制，恢复运行需要允许从 `main` 发起。
